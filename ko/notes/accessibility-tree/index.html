OpenAB Computer가 이제 macOS 접근성 트리를 읽습니다

2026-11-09 · OpenAB Computer 0.9.0

OpenAB Computer 0.9.0에 MCP 도구 ui_snapshot이 추가됐습니다. Mac 앱의 접근성 트리를 읽어 JSON으로 돌려줍니다. 이제 에이전트는 창 안의 버튼, 입력란, 레이블을 화면 위 위치와 함께 텍스트로 받습니다. 스크린샷을 보고 짐작할 필요가 없습니다.

스크린샷 루프로는 부족했던 이유

지금까지 OpenAB Computer로 Mac을 다루는 에이전트는 이렇게 움직였습니다. 스크린샷을 찍고, 버튼 위치를 짐작하고, mouse로 클릭하고, 다시 스크린샷을 찍어 확인합니다.

커뮤니티 사용자 ttmuse 님이 issue #67에 이 루프의 비용을 적어 주었습니다. 이 사용자는 OpenAB Computer를 매일, 집에 있는 Mac을 움직이는 클라우드 에이전트의 손으로 씁니다. 단계마다 이미지 토큰이 들고, 작은 대상은 빗나가고, 에이전트가 일하는 동안 실제 커서를 빼앗긴다는 내용이었습니다.

이 issue는 정말 필요로 하는 사람을 기다리고 있었습니다. 그 댓글로 실제로 필요한 사람이 있다는 것을 알게 되어 우선순위를 올리고 macOS부터 시작했습니다.

Agent Desktop에서 배운 것

코드를 쓰기 전에 Vercel Labs의 Agent Desktop을 꼼꼼히 읽었습니다. README, 개념 문서, 그리고 macOS 코드입니다. Agent Desktop은 데스크톱 앱의 접근성 트리를 읽어 JSON으로 돌려주고, 에이전트가 조작할 수 있는 요소마다 ref를 붙입니다. 그중 세 가지 생각이 우리 계획의 모양을 정했습니다. 앞의 두 가지는 지금의 ui_snapshot에 들어 있고, 세 번째는 2단계에서 다룹니다.

  • 이미지 대신 구조화된 텍스트. 모델은 역할, 이름, 값을 읽습니다. 픽셀 속에서 버튼을 찾지 않아도 됩니다.
  • 요소마다 하나의 ref, 한 번의 스냅샷에서. Agent Desktop의 ref는 그것을 만든 스냅샷에 속합니다. UI가 바뀌면 오래되었거나 모호한 ref는 짐작하지 않고 거부되고, 에이전트는 새 스냅샷을 찍습니다.
  • 포인터 없이 조작하기(2단계). Agent Desktop의 ref 동작은 접근성 API를 거치며 포인터를 움직이지 않고 포커스도 가져가지 않습니다.

issue #67에는 OpenAB Computer에서 Agent Desktop을 호출하는 방안도 있었습니다. 직접 관리할 코드는 줄지만 외부 의존성과 그 업데이트 주기를 떠안게 된다는 비교였습니다. 결국 접근성 트리를 OpenAB Computer 자체 MCP 도구 중 하나로 만들기로 했고, screenshot, mouse, key를 이미 제공하는 Swift 데몬에 넣었습니다(PR #93).

ui_snapshot이 돌려주는 것

기본으로는 맨 앞에 있는 앱의 포커스된 창을 읽습니다. app(bundle id나 앱 이름), pid, window, all_windows로 다른 대상을 고를 수 있습니다.

각 노드에는 역할, 제목, 값, 설명, 활성 여부와 포커스 여부, 그리고 frame이 들어 있습니다. frame은 screenshot, mouse와 같은 디스플레이 포인트 좌표를 쓰므로, 에이전트는 화면을 먼저 보지 않고도 노드를 겨냥해 클릭할 수 있습니다. 노드마다 ref(e1, e2, …)도 붙는데, 같은 스냅샷 ID 안에서는 겹치지 않습니다.

아래는 M4 Mac mini에서 Finder 창을 하나도 열지 않은 상태로 찍은 실제 스냅샷입니다. 이때 창은 데스크톱 자체이고, 그 안의 두 이미지는 마운트된 드라이브 두 개의 아이콘입니다. 도구는 모델이 읽을 텍스트 형식을 돌려줍니다.

ui_snapshot snap-10661573 · Finder (com.apple.finder) · 4 nodes · 104 ms
[e1] AXScrollArea desc="desktop" (0,0 1920×1080) focused
  [e2] AXGroup desc="desktop" (0,0 1920×1080) focused
    [e3] AXImage "Data" (1823,145 64×64)
    [e4] AXImage "Backup" (1823,33 64×64)

같은 트리의 JSON(발췌, 일부 필드는 생략):

{
  "snapshot_id": "snap-10661573",
  "app": { "name": "Finder", "bundle_id": "com.apple.finder" },
  "node_count": 4,
  "truncated": false,
  "timed_out": false,
  "elapsed_ms": 104,
  "windows": [
    { "ref": "e1", "role": "AXScrollArea", "description": "desktop",
      "focused": true,
      "frame": { "x": 0, "y": 0, "width": 1920, "height": 1080 },
      "children": [
        { "ref": "e2", "role": "AXGroup", "description": "desktop",
          "focused": true,
          "frame": { "x": 0, "y": 0, "width": 1920, "height": 1080 },
          "children": [
            { "ref": "e3", "role": "AXImage", "title": "Data",
              "frame": { "x": 1823, "y": 145, "width": 64, "height": 64 } }
          ] }
      ] }
  ]
}

노드 네 개를 104 ms에 읽었습니다. 드라이브 이름은 여기서 일반적인 이름으로 바꿨습니다. “Data” 드라이브를 열려면 에이전트는 e3 frame의 중심 (1855, 177)을 더블클릭하면 되고, 위치를 찾으려고 스크린샷을 찍을 필요가 없습니다.

한도, 타임아웃, 프라이버시

스냅샷에는 한도가 있습니다. 기본으로 깊이 20단계나 노드 300개에서 멈추고, 호출 전체에 3초를 줍니다. 호출하는 쪽은 50단계, 노드 2,000개, 10초까지 올릴 수 있습니다. 접근성 호출 전마다 최대 0.5초의 메시지 타임아웃을 걸기 때문에, 응답을 멈춘 앱이 도구를 붙잡아 둘 수 없습니다.

한도나 시간이 다 되면 에이전트는 그때까지 읽은 부분을 truncated나 timed_out 표시와 함께 받고, 오류는 나지 않습니다. 긴 텍스트는 앞의 200자만 읽으므로 큰 문서가 통째로 복사되지 않습니다.

비밀번호 입력란은 항상 가립니다. 보안 텍스트 필드에 대해서는 도구가 값을 아예 요청하지 않고 안쪽도 읽지 않습니다. 다른 입력란은 가리지 않습니다.

이 점이 중요한 이유는 트리에 스크린샷에 보이지 않는 텍스트도 들어 있기 때문입니다. 스크롤로 가려진 행, 접힌 내용, 다른 창. 그래서 ui_snapshot은 owner 프로필에서만 쓸 수 있고, macOS 손쉬운 사용(Accessibility) 권한이 필요합니다. mouse와 key가 이미 쓰는 바로 그 권한입니다.

어떤 화면에 어떤 도구를

  • 네이티브 Mac 앱: ui_snapshot.
  • 웹 페이지: browser_snapshot. 브라우저에서 페이지 구조를 읽습니다.
  • canvas처럼 직접 그린, 접근성 트리가 없는 내용: 예전처럼 screenshot과 mouse.

Agent Desktop과 같은 점, 아직 다른 점

같은 점: 둘 다 macOS 접근성 API를 읽고 이미지 대신 JSON을 돌려줍니다. 둘 다 요소에 한 번의 스냅샷 안에서만 유효한 ref를 붙입니다. 우리는 모든 노드에, Agent Desktop은 에이전트가 조작할 수 있는 요소에 붙입니다. 둘 다 다 읽지 못하면 실패하는 대신 일부 트리를 돌려줍니다. 둘 다 안에 모델이 없고, 루프는 호출하는 에이전트가 돌립니다.

지금 다른 점:

  • OpenAB Computer는 읽기만 합니다. Agent Desktop은 이미 ref로 클릭, 입력, 값 설정, 포커스 이동을 하고 포인터도 움직이지 않습니다. OpenAB Computer의 에이전트는 여전히 mouse로 좌표를 클릭하고, 실제 커서는 여전히 움직입니다.
  • ref. 우리 ref는 한 스냅샷의 레이블일 뿐이고 도구는 상태를 두지 않습니다. Agent Desktop은 ref마다 요소를 식별할 정보를 저장해 두고, 동작하기 전에 같은 요소인지 확인합니다.
  • 플랫폼. OpenAB Computer가 트리를 읽는 곳은 아직 macOS뿐입니다. Agent Desktop은 macOS, Windows, Linux를 지원합니다.
  • 형태. ui_snapshot은 원격 MCP 서버의 도구 하나로, 다른 기기의 에이전트가 씁니다. Agent Desktop은 로컬에서 CLI, C 라이브러리, 또는 stdio MCP 서버로 실행됩니다.

읽어 볼 만한 비교 글

Muse의 리서치 글이 OpenCode Browse와 OpenAB Computer를 비교합니다. 요점은 이렇습니다. Browse는 에이전트가 내 기기에서 로그인된 실제 브라우저를 다루게 하고, OpenAB Computer는 기기 한 대를 통째로 다른 곳의 에이전트에게 빌려줍니다. ui_snapshot 덕분에 그 원격 에이전트는 이제 브라우저뿐 아니라 네이티브 앱도 구조화된 텍스트로 읽을 수 있습니다.

다음 단계(아직 출시 전)

2단계는 ui_action(ref)입니다. ref로 버튼 누르기, 입력란 값 설정, 포커스 이동, 메뉴 열기를 커서를 움직이지 않고 합니다. 커서를 빼앗기는 문제를 끝내는 것이 이 부분입니다. 지금 트리에 빠져 있는 메뉴 막대도 이때 추가합니다. 비밀번호 입력란에 값을 설정하는 것은 거부합니다.

macOS 다음으로는 AT-SPI 기반의 Linux 버전을 계획하고 있습니다. 둘 다 일정은 정해지지 않았고, issue #67을 열어 둔 채 둘 다 추적합니다.

써 보려면 OpenAB Computer 0.9.0으로 업데이트하고 손쉬운 사용 권한을 준 뒤, owner 프로필의 에이전트에서 ui_snapshot을 호출하세요.
