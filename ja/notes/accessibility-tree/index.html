OpenAB Computer が macOS のアクセシビリティツリーを読めるようになりました

2026-11-09 · OpenAB Computer 0.9.0

OpenAB Computer 0.9.0 で、MCP ツール ui_snapshot が加わりました。Mac アプリのアクセシビリティツリーを読み、JSON で返します。エージェントは、ウィンドウの中のボタンや入力欄やラベルを、画面上の位置とあわせてテキストで受け取れます。スクリーンショットから読み解く必要はもうありません。

スクリーンショットのループでは足りなかった理由

これまで、OpenAB Computer で Mac を操作するエージェントはこう動いていました。スクリーンショットを撮り、ボタンの位置を推測し、mouse でクリックし、もう一度スクリーンショットで確かめる。

コミュニティのユーザー ttmuse さんが、issue #67 でこのループのコストを書いてくれました。この方は OpenAB Computer を毎日、自宅の Mac を動かすクラウドのエージェントの手として使っています。一手ごとに画像のトークンがかかり、小さな対象は外れ、エージェントが動いている間は本物のカーソルを取られてしまう、というものです。

この issue は、本当に必要とする人を待っていました。このコメントで実際に必要な人がいるとわかったので、優先度を上げ、macOS から取りかかりました。

Agent Desktop から学んだこと

コードを書く前に、Vercel Labs の Agent Desktop をじっくり読みました。 README、コンセプトの文書、そして macOS のコードです。Agent Desktop はデスクトップアプリのアクセシビリティツリーを読んで JSON で返し、エージェントが操作できる要素ごとに ref を付けます。そのうち三つの考え方が私たちの計画を形づくりました。最初の二つは今の ui_snapshot に入っていて、三つ目は第 2 段階で取り組みます。

  • 画像ではなく構造化されたテキスト。モデルが読むのはロール、名前、値です。ピクセルの中からボタンを探す必要はありません。
  • 要素ごとの ref は、一回のスナップショットのもの。Agent Desktop の ref は、それを作ったスナップショットに属します。UI が変われば、古い ref や曖昧な ref は推測せずに拒否され、エージェントは新しいスナップショットを撮ります。
  • ポインターを使わない操作（第 2 段階）。Agent Desktop の ref による操作はアクセシビリティ API を通り、ポインターを動かさず、フォーカスも奪いません。

issue #67 では、OpenAB Computer から Agent Desktop を呼び出す案も挙げていました。自分で持つコードが減る一方で、外部への依存とその更新のペースを抱えることになる、という比較です。最終的に、アクセシビリティツリーを OpenAB Computer 自身の MCP ツールの一つにすることにし、 screenshot、mouse、key をすでに提供している Swift のデーモンに入れました（PR #93）。

ui_snapshot が返すもの

既定では、最前面のアプリのフォーカスされたウィンドウを読みます。app（bundle id かアプリ名）、pid、window、all_windows で別の対象を選べます。

各ノードには、ロール、タイトル、値、説明、有効かどうかとフォーカスの有無、そして frame が入ります。frame は screenshot や mouse と同じディスプレイのポイント座標なので、エージェントは画面を見なくてもノードを狙ってクリックできます。各ノードには ref （e1、e2…）も付き、同じスナップショット ID の中では重複しません。

以下は、M4 Mac mini で Finder のウィンドウを一つも開いていないときに撮った、実際のスナップショットです。この場合のウィンドウはデスクトップそのもので、中の二つの画像はマウントされた二台のドライブのアイコンです。ツールはモデル向けのテキスト版を返します。

ui_snapshot snap-10661573 · Finder (com.apple.finder) · 4 nodes · 104 ms
[e1] AXScrollArea desc="desktop" (0,0 1920×1080) focused
  [e2] AXGroup desc="desktop" (0,0 1920×1080) focused
    [e3] AXImage "Data" (1823,145 64×64)
    [e4] AXImage "Backup" (1823,33 64×64)

同じツリーの JSON（抜粋。一部のフィールドは省いています）：

{
  "snapshot_id": "snap-10661573",
  "app": { "name": "Finder", "bundle_id": "com.apple.finder" },
  "node_count": 4,
  "truncated": false,
  "timed_out": false,
  "elapsed_ms": 104,
  "windows": [
    { "ref": "e1", "role": "AXScrollArea", "description": "desktop",
      "focused": true,
      "frame": { "x": 0, "y": 0, "width": 1920, "height": 1080 },
      "children": [
        { "ref": "e2", "role": "AXGroup", "description": "desktop",
          "focused": true,
          "frame": { "x": 0, "y": 0, "width": 1920, "height": 1080 },
          "children": [
            { "ref": "e3", "role": "AXImage", "title": "Data",
              "frame": { "x": 1823, "y": 145, "width": 64, "height": 64 } }
          ] }
      ] }
  ]
}

四つのノードを 104 ms で読みました。ドライブ名はここでは一般的な名前に置き換えています。「Data」ドライブを開きたければ、エージェントは e3 の frame の中心 (1855, 177) をダブルクリックすればよく、場所を探すためのスクリーンショットはいりません。

上限、タイムアウト、プライバシー

スナップショットには上限があります。既定では深さ 20 階層か 300 ノードで止まり、呼び出し全体に 3 秒を割り当てます。呼び出し側は 50 階層、2,000 ノード、10 秒まで引き上げられます。アクセシビリティの呼び出しの前には毎回、最大 0.5 秒のメッセージタイムアウトを設定するので、応答しなくなったアプリに止められることはありません。

上限や時間に達したときは、それまでに読めた分を truncated か timed_out の印付きで返し、エラーにはしません。長いテキストは先頭 200 文字だけを読むので、大きな文書が丸ごとコピーされることはありません。

パスワード欄は必ずマスクします。セキュアテキストフィールドについては、ツールは値を一切問い合わせず、中も読みません。それ以外の入力欄はマスクしません。

これが大事なのは、ツリーにはスクリーンショットに写らないテキストも入っているからです。スクロールで隠れた行、折りたたまれた内容、ほかのウィンドウ。そのため ui_snapshot は owner プロファイルでしか使えず、macOS のアクセシビリティ権限が必要です。 mouse と key がすでに使っているのと同じ権限です。

どの画面にどのツールを使うか

  • ネイティブの Mac アプリ：ui_snapshot。
  • Web ページ：browser_snapshot。ブラウザーからページの構造を読みます。
  • canvas のように独自に描画された、アクセシビリティツリーのない内容：これまでどおり screenshot と mouse。

Agent Desktop と同じところ、まだ違うところ

同じところ：どちらも macOS のアクセシビリティ API を読み、画像ではなく JSON を返します。どちらも要素に、一回のスナップショットの中でだけ有効な ref を付けます。こちらはすべてのノードに、Agent Desktop はエージェントが操作できる要素に付けます。どちらも、読み切れないときは失敗せずに部分的なツリーを返します。どちらも中にモデルを持たず、ループは呼び出すエージェントが回します。

今のところ違うところ：

  • OpenAB Computer は読むだけです。Agent Desktop はすでに、ref でクリック、入力、値の設定、フォーカスの移動ができ、ポインターも動かしません。OpenAB Computer のエージェントは今も mouse で座標をクリックするので、本物のカーソルは動きます。
  • ref。こちらの ref は一回のスナップショットのラベルにすぎず、ツールは状態を持ちません。Agent Desktop は ref ごとに要素を特定するための情報を保存し、操作の前に同じ要素であることを確かめます。
  • プラットフォーム。OpenAB Computer がツリーを読めるのは今のところ macOS だけです。 Agent Desktop は macOS、Windows、Linux に対応しています。
  • 形。ui_snapshot はリモートの MCP サーバーにあるツールの一つで、別のマシンのエージェントが使います。Agent Desktop はローカルで、CLI、C ライブラリー、または stdio の MCP サーバーとして動きます。

読む価値のある比較記事

Muse のリサーチ記事が、OpenCode Browse と OpenAB Computer を比べています。要点は、Browse はエージェントに自分のマシンにある、ログイン済みの本物のブラウザーを操作させ、 OpenAB Computer はマシン一台を丸ごと別の場所のエージェントに貸す、ということです。 ui_snapshot によって、そのリモートのエージェントはブラウザーだけでなく、ネイティブアプリも構造化されたテキストとして読めるようになりました。

次にやること（まだリリースしていません）

第 2 段階は ui_action(ref) です。ref を使って、ボタンを押す、入力欄に値を設定する、フォーカスを移す、メニューを開く、といった操作をカーソルを動かさずに行います。カーソルを取られる問題を解消するのはこの部分です。今のツリーには入っていないメニューバーもここで加えます。パスワード欄への値の設定は拒否します。

macOS の次は、AT-SPI を使った Linux 版を予定しています。どちらも日程は決まっていません。 issue #67 は開いたままにして、両方を追いかけます。

試すには、OpenAB Computer 0.9.0 に更新してアクセシビリティ権限を与え、 owner プロファイルのエージェントから ui_snapshot を呼んでください。
