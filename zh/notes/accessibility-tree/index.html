OpenAB Computer 開始支援 macOS 的 accessibility tree

2026-11-09 · OpenAB Computer 0.9.0

OpenAB Computer 0.9.0 新增了 ui_snapshot 這個 MCP 工具：讀取 Mac app 的 accessibility tree，以 JSON 回傳。agent 現在可以直接用文字看到視窗裡的按鈕、欄位和標籤，連同它們在螢幕上的位置，不必再從截圖裡猜。

為什麼截圖迴圈不夠用

在這之前，agent 透過 OpenAB Computer 操作 Mac，走的是這樣的迴圈：截圖、猜按鈕在哪裡、用 mouse 點下去，再截一張圖確認。

社群使用者 ttmuse 在 issue #67 寫下了這個迴圈的代價。這位使用者每天把 OpenAB Computer 當成雲端 agent 的手，遠端操作家裡的 Mac。每一步都要花圖片 token，小目標常常點不到，agent 工作時，真正的游標也被搶走了。

這個 issue 原本在等一個真正需要它的人。這則留言說明了有人真的需要，於是我們調高了優先順序，先從 macOS 開始做。

從 Agent Desktop 學到的事

動手之前，我們仔細讀了 Vercel Labs 的 Agent Desktop：README、概念文件，還有 macOS 的程式碼。Agent Desktop 讀取桌面 app 的 accessibility tree，以 JSON 回傳，每個 agent 能操作的元素都配有一個 ref。其中三個想法影響了我們的規劃：前兩個已經做進 ui_snapshot，第三個要等第二階段。

  • 用結構化的文字取代圖片。模型讀的是角色、名稱和值，不用在像素裡找按鈕。
  • 每個元素一個 ref，來自某一次快照。Agent Desktop 的 ref 只屬於產生它的那次快照。畫面一變，過期或對不上的 ref 會直接被拒絕，不會用猜的，agent 重新拍一次快照就好。
  • 操作不靠游標（第二階段）。Agent Desktop 用 ref 執行的動作走 accessibility API，不移動游標，也不搶走焦點。

issue #67 當初也列過另一個做法：讓 OpenAB Computer 直接呼叫 Agent Desktop，好處是自己要維護的程式碼比較少，代價是多一個外部依賴，也得跟著它的更新節奏走。最後我們決定把 accessibility tree 做成 OpenAB Computer 自己的 MCP 工具之一，放進原本就提供 screenshot、mouse、 key 的那支 Swift 常駐程式（PR #93）。

ui_snapshot 回傳什麼

預設讀取最前面那個 app 目前的焦點視窗。用 app（bundle id 或 app 名稱）、 pid、window 和 all_windows 可以換成別的目標。

每個節點都帶有角色、標題、值、說明、是否啟用或取得焦點，以及一個 frame。frame 用的是和 screenshot、mouse 相同的顯示點座標，所以 agent 不用先看螢幕，就能對準節點點下去。每個節點也有一個 ref（e1、e2⋯⋯），在同一個快照 id 之內不會重複。

下面是在一台 M4 Mac mini 上對 Finder 拍的真實快照，當時沒有開任何 Finder 視窗，所以這個「視窗」就是桌面本身，裡面兩張圖是兩顆已掛載磁碟的圖示。工具會回傳一份給模型讀的文字版：

ui_snapshot snap-10661573 · Finder (com.apple.finder) · 4 nodes · 104 ms
[e1] AXScrollArea desc="desktop" (0,0 1920×1080) focused
  [e2] AXGroup desc="desktop" (0,0 1920×1080) focused
    [e3] AXImage "Data" (1823,145 64×64)
    [e4] AXImage "Backup" (1823,33 64×64)

{

      "focused": true,

      "children": [

四個節點，花了 104 ms。磁碟名稱在這裡換成了通用名稱。agent 想打開「Data」這顆磁碟，只要對 e3 的 frame 中心 (1855, 177) 按兩下，不必先截圖找它在哪裡。

上限、逾時與隱私

一次快照有上限。預設最多往下 20 層或 300 個節點，整個呼叫給 3 秒；呼叫端可以調高到 50 層、 2,000 個節點和 10 秒。每次呼叫 accessibility API 之前，工具都會設定最多半秒的訊息逾時，所以一個已經沒有回應的 app 拖不住它。

碰到上限或時間用完時，agent 拿到的是目前已經讀到的部分，標上 truncated 或 timed_out，不會變成錯誤。很長的文字只讀前 200 個字元，大份文件不會被整份複製出來。

密碼欄位一律遮蔽。遇到安全文字欄位，工具根本不會去要它的值，也不會往裡面讀。其他欄位則不遮蔽。

這點很重要，因為這棵樹裡有截圖看不到的文字：捲到畫面外的列、收合起來的內容、其他視窗。所以 ui_snapshot 只開放給 owner profile，而且需要 macOS 的「輔助使用」權限，也就是 mouse 和 key 本來就在用的那一個。

哪種畫面用哪個工具

  • 原生 Mac app：ui_snapshot。
  • 網頁：browser_snapshot，從瀏覽器讀取頁面結構。
  • 自己繪製的內容，例如 canvas，沒有 accessibility tree：照舊用 screenshot 加 mouse。

和 Agent Desktop 一樣的地方，以及還不一樣的地方

一樣的：兩者都讀 macOS 的 accessibility API，回傳 JSON 而不是圖片；都替元素配上只在單次快照內有效的 ref，差別是我們替每個節點都配，Agent Desktop 只替 agent 能操作的元素配；讀不完時都回傳部分的樹，而不是直接失敗；兩者裡面都沒有模型，迴圈由呼叫它的 agent 自己跑。

目前不一樣的：

  • OpenAB Computer 只能讀。Agent Desktop 已經能用 ref 點擊、輸入、設定值、移動焦點，而且不動游標。用 OpenAB Computer 的 agent 還是得用 mouse 點座標，真正的游標還是會動。
  • ref。我們的 ref 只是單次快照裡的標籤，工具本身不保留狀態。Agent Desktop 會把每個 ref 對應到辨識元素用的資訊並存下來，動作之前先確認還是同一個元素。
  • 平台。OpenAB Computer 目前只在 macOS 上讀得到這棵樹，Agent Desktop 支援 macOS、Windows 和 Linux。
  • 形式。ui_snapshot 是遠端 MCP server 裡的一個工具，給另一台機器上的 agent 使用。Agent Desktop 則在本機以 CLI、C 函式庫或 stdio MCP server 的形式執行。

一篇值得一讀的比較

Muse 上有一篇研究文章比較了 OpenCode Browse 和 OpenAB Computer。重點是：Browse 讓 agent 在你自己的電腦上操作你已經登入的那個瀏覽器，OpenAB Computer 則是把一整台機器借給在別處的 agent。有了 ui_snapshot，這個遠端 agent 除了瀏覽器，也能用結構化的文字讀原生 app 了。

接下來（尚未推出）

第二階段是 ui_action(ref)：用 ref 按按鈕、設定欄位的值、移動焦點或打開選單，不移動游標。真正解決游標被搶走的，是這一段。它也會把目前樹裡沒有的選單列加進來。對密碼欄位設定值則會被拒絕。

macOS 之後，規劃中的是以 AT-SPI 為基礎的 Linux 版本。兩者都還沒有時程，issue #67 會繼續開著追蹤。
