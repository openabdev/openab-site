我們怎麼測試 OpenAB Computer 0.10.0 的 ui_action

2026-11-10 · OpenAB Computer 0.10.0

上一篇開發筆記介紹了 ui_snapshot。那是第一階段（OpenAB Computer 0.9.0）：agent 讀得到 Mac app 的 accessibility tree，但還不能操作。這篇搭配 OpenAB Computer 0.10.0 的發布，新增的 ui_action 讓 agent 可以直接操作這棵樹：帶著快照的 snapshot_id 和 ref，做 press、set_value、focus、show_menu、confirm 或 cancel，游標不會移動。

那麼，從讀樹、動手到確認結果，整個操作過程要怎麼測？

我們怎麼測

單元測試：用假的 accessibility 提供者

CI 機器沒有螢幕，所以單元測試從不碰真的 app，而是跑在一個假的 accessibility 提供者上。它模擬出視窗、按鈕和文字欄位，讓測試逐條檢查 ui_action 的規則：

  • ref 只在產生它的那次快照裡有效。快照過期、被擠出快取，或 ref 不存在，都會被拒絕。
  • 快照之後元素變了（消失、角色改變、換了行程，或離開原本的視窗），這個 ref 就過期了。工具會拒絕，請 agent 重拍快照，不會挑一個長得像的元素代替。
  • 元素不支援的動作，在動手前就拒絕，並列出它支援哪些動作。
  • 密碼欄位的值不會被讀回，也不會寫進紀錄或出現在回應裡。
  • 除非呼叫端傳 activate: true，否則不會把 app 叫到前景。
  • 只有 owner profile 能呼叫 ui_action。

PR #96 新增了 52 個這類測試。在一台 M4 Mac mini 上，整套 swift test 跑了 256 個測試，0 個失敗，PR 上的 CI 檢查也全部通過。

實機端到端測試：一台 M4 Mac mini

單元測試確認規則沒錯，實機測試則確認整件事在真的 app 上做得到。我們讓 agent 經過 switchboard 操作一台 M4 Mac mini，走的是遠端 agent 平常用的同一條網路路徑：

  1. 讀一次滑鼠位置。
  2. 打開 TextEdit，開一份新文件。
  3. 呼叫 ui_snapshot，在樹裡找到文字區（AXTextArea）和它的 ref。
  4. 用 ui_action 對這個 ref 做 focus，再用 set_value 寫入一句話。
  5. 再呼叫一次 ui_snapshot，確認文字區的值就是那句話。
  6. 再讀一次滑鼠位置，和第一次比對。

兩次讀到的是同一個點：文字寫進去了，游標沒有動。下面的效能測試又把 tree 路徑跑了 10 次，每次文字都寫進文件，游標也都沒動。

此外，每個變更都交給兩個使用不同模型的獨立 AI 審查者，兩邊都核准同一個 commit 才會合併。

效能改進有多少

我們拿同一件事，用兩種方式各做 10 次：在新的空白 TextEdit 文件裡輸入 The quick brown fox jumps over the lazy dog.（44 個字元），再確認它寫進去了。

  • A) 截圖迴圈：screenshot → 用 mouse 點文字區 → 用 key 輸入 → 再 screenshot 確認。
  • B) tree 路徑：ui_snapshot → ui_action focus → ui_action set_value → 再 ui_snapshot 確認。

在這個任務上，A 用掉的輸入 token 在一般模型上約是 B 的 2.2 倍（3,165 對 1,435），在高解析度模型上約是 3.8 倍（5,427 對 1,435）。B 花 0.36 秒做完，A 要 1.70 秒，B 約快 4.7 倍，而且游標從頭到尾沒動。

A 的時間主要花在用鍵盤送出 44 個按鍵（877 ms），以及兩張各約 500 KB 的截圖經過 switchboard 傳回來。B 的每次 ui_action 呼叫端到端約 67 ms，大部分是網路往返。

token 怎麼算：圖片用 Anthropic vision 指南的公式，先把圖縮到模型的上限內，再算 ⌈寬/28⌉ × ⌈高/28⌉。一般模型（長邊上限 1,568 px）會把 1920×1080 的截圖縮成 1456×819，約 1,560 個 token；高解析度模型（長邊上限 2,576 px）不縮，約 2,691 個 token。文字以約 4 個字元算 1 個 token，沒有跑 tokenizer。只算模型實際會看到的內容，不含工具定義和模型自己的輸出。

測試條件：一台 M4 Mac mini（16 GB、macOS 15.7），一個 1920×1080 的螢幕，裝的是 OpenAB Computer 0.10.0。agent 經 tailnet 用 HTTPS 連到 switchboard，再轉到這台 Mac mini，每次呼叫都要付這段往返。A、B 各跑 10 次，交錯進行，最前面一組暖身不計。只計四次工具呼叫的時間。A 點擊的座標取自已知的視窗位置，真的模型得先從第一張截圖裡找出來。這些數字來自一台機器、一個任務，也不包含模型看截圖或快照、思考下一步的時間。
