OpenAB Computer can now read the macOS accessibility tree

2026-11-09 · OpenAB Computer 0.9.0

OpenAB Computer 0.9.0 adds ui_snapshot, an MCP tool that reads the accessibility tree of a Mac app and returns it as JSON. An agent can now see the buttons, fields and labels in a window as text, with their positions on screen, instead of working them out from a screenshot.

Why the screenshot loop was not enough

Until now, an agent using OpenAB Computer on a Mac worked in a loop: take a screenshot, guess where a button is, click it with mouse, then take another screenshot to check.

A community user, ttmuse, described the cost of that loop on issue #67. They use OpenAB Computer every day as the hands of a cloud agent that drives a home Mac. Every step costs image tokens, small targets get missed, and the real cursor is taken over while the agent works.

The issue had been waiting for a real user. The comment showed there was one, so we raised its priority and started with macOS.

What we learned from Agent Desktop

Before writing code we read Vercel Labs' Agent Desktop closely: its README, its concept docs and its macOS code. Agent Desktop reads the accessibility tree of a desktop app and returns it as JSON, with a ref for every element an agent can act on. Three of its ideas shaped our plan: the first two are in ui_snapshot today, and the third waits for phase 2.

  • Structured text instead of images. The model reads roles, names and values. It does not have to find a button in pixels.
  • A ref per element, from one snapshot. Agent Desktop's refs belong to the snapshot that produced them. When the UI changes, a stale or ambiguous ref is rejected instead of guessed, and the agent takes a new snapshot.
  • Acting without the pointer (phase 2). Agent Desktop's ref actions go through the accessibility API without moving the pointer or taking focus.

Issue #67 listed calling Agent Desktop from OpenAB Computer as one option, and weighed less code to own against an external dependency and its release cadence. We decided to make the accessibility tree one of OpenAB Computer's own MCP tools, in the Swift daemon that already serves screenshot, mouse and key (PR #93).

What ui_snapshot returns

By default it reads the focused window of the frontmost app. app (a bundle id or name), pid, window and all_windows pick another target.

Each node carries its role, title, value and description, whether it is enabled or focused, and a frame. The frame uses the same display points as screenshot and mouse, so an agent can aim a click at a node without looking at the screen first. Every node also gets a ref (e1, e2, …) that is unique within that snapshot's id.

Here is a real snapshot of Finder on an M4 Mac mini, taken with no Finder window open. The window is the desktop itself, and the two images in it are the icons of two mounted drives. The tool returns a text form for the model:

[e1] AXScrollArea desc="desktop" (0,0 1920×1080) focused
  [e2] AXGroup desc="desktop" (0,0 1920×1080) focused
    [e3] AXImage "Data" (1823,145 64×64)
    [e4] AXImage "Backup" (1823,33 64×64)

Four nodes, read in 104 ms. The drive names are replaced with generic ones here. To open the “Data” drive, an agent can double-click the center of e3's frame, (1855, 177), without taking a screenshot to find it.

Limits, timeouts and privacy

A snapshot is bounded. By default it stops at 20 levels deep or 300 nodes, and the whole call gets 3 seconds; a caller can raise these to 50 levels, 2,000 nodes and 10 seconds. Before every accessibility call the tool sets a messaging timeout of at most half a second, so an app that has stopped responding cannot block it.

When a limit or the time budget runs out, the agent gets what was read so far, flagged with truncated or timed_out, and no error. Long text is read as a 200-character prefix, so a large document is not copied whole.

Password fields are always masked. For a secure text field the tool never asks for the value and does not look inside it. Other fields are not masked.

That matters because the tree holds text a screenshot does not show: rows scrolled out of view, collapsed content, other windows. So ui_snapshot is available only to the owner profile, and it needs the macOS Accessibility permission, the same one mouse and key already use.

Which tool for which screen

  • Native Mac apps: ui_snapshot.
  • Web pages: browser_snapshot, which reads the page structure from the browser.
  • Custom-drawn content such as canvases, which has no accessibility tree: screenshot and mouse, as before.

Where we match Agent Desktop, and where we don't yet

The same: both read the macOS accessibility API and return JSON, not images. Both give elements refs that are valid only within one snapshot. Ours label every node; Agent Desktop's label the elements an agent can act on. Both return a partial tree instead of failing. Neither has a model inside; the calling agent runs the loop.

Different, today:

  • OpenAB Computer only reads. Agent Desktop can already click, type, set values and move focus by ref without moving the pointer. An agent on OpenAB Computer still clicks with mouse at coordinates, and the real cursor still moves.
  • Refs. Our refs only label one snapshot; the tool keeps no state. Agent Desktop stores a map from each ref to evidence of the element's identity, and checks it is the same element before acting.
  • Platforms. OpenAB Computer reads the tree on macOS only. Agent Desktop covers macOS, Windows and Linux.
  • Shape. ui_snapshot is one tool in a remote MCP server, used by an agent on another machine. Agent Desktop runs locally as a CLI, a C library or a stdio MCP server.

A comparison worth reading

A research write-up on Muse compares OpenCode Browse with OpenAB Computer. Its main point: Browse lets an agent drive your real, logged-in browser on your own machine, while OpenAB Computer lends a whole machine to an agent somewhere else. With ui_snapshot, that remote agent can now read native apps as structured text, not only the browser.

What's next (not shipped)

Phase 2 is ui_action(ref): press a button, set a field's value, move focus or open a menu by ref, without moving the cursor. That is the part that ends the cursor takeover. It will also add the menu bar, which today's tree leaves out. Setting a value on a password field will be refused.

After macOS, a Linux version based on AT-SPI is planned. Neither has a date. Issue #67 stays open to track both.

To try it, update to OpenAB Computer 0.9.0, give it the Accessibility permission, and call ui_snapshot from an agent with the owner profile.
